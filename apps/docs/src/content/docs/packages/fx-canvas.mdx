Lightweight WebGL shader background runtime for websites. It is **not** a
scene, camera, mesh, or full rendering-engine abstraction — it creates and
manages a WebGL canvas for an existing DOM region, then lets you drive a
fragment shader with built-in uniforms, custom uniforms, textures, and an
optional previous-frame feedback pass.

```sh
pnpm add @frapx/fx-canvas
```

```ts
import { createShaderBackground, glsl } from "@frapx/fx-canvas";

createShaderBackground({
  target: ".hero",
  fragment: glsl`
    precision highp float;
    uniform vec2 u_resolution;
    uniform float u_time;

    void main() {
      vec2 uv = gl_FragCoord.xy / u_resolution;
      gl_FragColor = vec4(uv, 0.5 + 0.5 * sin(u_time), 1.0);
    }
  `
});
```

## What it handles for you

- **Canvas setup & resize** — inserts and sizes a canvas over `target`, tracks `ResizeObserver`.
- **Lifecycle & a11y** — pauses the render loop offscreen, on hidden tabs, and (opt-in) under `prefers-reduced-motion`. Always supplies `u_reducedMotion` so you can react in-shader too.
- **Built-in uniforms** — `u_time`, `u_delta`, `u_resolution`, `u_viewportSize`, `u_pixelRatio`, `u_pointer`, `u_pointerUv`, `u_pointerActive`, `u_reducedMotion`.
- **WebGL1 and WebGL2** — start your fragment with `#version 300 es` to opt into GLSL ES 3.00; everything else stays WebGL1 by default.
- **Textures** — image URL / `HTMLImageElement` / `HTMLCanvasElement` sources, with runtime updates via `setTexture()` / `setTextures()`.
- **Feedback** — `feedback: true` gives you a managed ping-pong framebuffer exposed as `u_previousFrame` for effects that need to read the previous frame. `feedback: { format: "rgba16f" }` uses half-float buffers on WebGL2 for accumulation without banding.
- **Deterministic rendering** — `clock: "manual"` + `setTime()` / `render()` draws exactly when you ask, and `resolution` fixes the render size, for frame-accurate output such as video frames.
- **External time** — `timeSource` makes the realtime loop follow an audio transport or any other clock, keeping the lifecycle gates.

## Deterministic rendering

```ts
const fx = createShaderBackground({
  target: ".stage",
  fragment,
  clock: "manual",
  resolution: [3840, 2160]
});
await fx.ready;

fx.setTime(1.5);                     // sets u_time only
const png = await fx.captureFrame(); // draws now and returns a PNG Blob
```

Under a manual clock nothing renders on its own, offscreen/hidden/reduced-motion
pausing is bypassed, and `u_pointer*` / `u_reducedMotion` stay at 0 — the same
time and uniforms always produce the same pixels. `setClock()` switches between
`"realtime"` and `"manual"` at runtime, and `setResolution([w, h] | null)`
changes or releases the fixed size. With `resolution` set, the canvas is
letterboxed (`object-fit: contain`) and `u_pixelRatio` is derived from the
internal and displayed sizes. Passing neither `target` nor `canvas` renders into
a detached canvas.

`captureFrame()` draws and reads back in the same task, since the drawing buffer
is not preserved. It returns a PNG `Blob` by default, or raw top-row-first RGBA
with `{ format: "rgba8" }` (`Uint8Array`) and `{ format: "rgba16f" }`
(`Float32Array`, read from float feedback buffers).

### Following an audio transport

```ts
const fx = createShaderBackground({
  target: ".hero",
  fragment,
  respectReducedMotion: true,
  timeSource: () => transport.getPositionMs() / 1000 // seconds
});
```

Every animation frame takes `u_time` from the source as is. `u_delta` is the
step from the previous frame, clamped to 0.1 s, and 0 when the source goes back
(a seek or a loop) or on the first frame after a pause. Unlike the manual clock,
the gates keep working: offscreen and hidden stop drawing and read the source
again on resume, reduced motion holds a still frame at the source's time, and
the pointer uniforms work. `render()` and `captureFrame()` redraw at the last
frame's time. `setTimeSource(fn | null)` changes or removes the source; a manual
clock ignores it but keeps it.

Do not align a plain realtime clock once with `setTime()` at play. It counts
animation frame timestamps, not the transport, so it starts 30–40 ms off and
drifts further on every loop when the audio and visual loop lengths differ, and
it cannot follow seeks or pauses.

### Float feedback

`feedback: { format: "rgba16f" }` needs WebGL2 with `EXT_color_buffer_float`
and requests a WebGL2 context even for GLSL ES 1.00 shaders. When float buffers
are unavailable it warns and uses `rgba8`; `formatFallback: false` makes that an
`UnsupportedError` instead. `fx.feedbackFormat` reports what was allocated, and
`fx.resetFeedback()` clears the history.

## Instance API

```ts
fx.ready;
fx.start();
fx.stop();
fx.render();
fx.resize();
fx.destroy();
fx.setTime(2.5);
fx.setClock("manual");
fx.setTimeSource(() => audio.currentTime); // or null
fx.setResolution([1920, 1080]);
await fx.captureFrame({ format: "png" });
fx.feedbackFormat;
fx.resetFeedback();
fx.setFragment(nextFragment); // ShaderCompileError | null; see "Hot reloading"
fx.setUniform("progress", 0.5);
fx.setUniforms({ progress: 0.5, color: [1, 0, 0] });
await fx.setTexture("image", "/next-hero.webp");
await fx.setTextures({ image: "/next-hero.webp" });
```

`ready` resolves once the first setup finishes. It rejects with `DestroyedError`
when `destroy()` runs first, with `UnsupportedError` when WebGL (or a feature
the instance needs) is unavailable, and with the setup error, such as a
`ShaderCompileError`, when initialization fails. Leaving `ready` unawaited after
`destroy()` or in an unsupported environment does not produce an unhandled
rejection, so a React StrictMode effect that destroys the instance in cleanup
stays quiet. Setup failures and a missing target still surface as unhandled
rejections when `ready` is left unhandled, even with `onError`.

`onResize(state)` runs whenever the render size actually changes (not on setup,
but also after `setResolution()`), for work that depends on the size, such as
picking a quality level.

`onStatusChange(status)` runs with the new value each time `fx.status` changes
(for example `"paused"` in a hidden tab, or `"context-lost"`), so a page can
show a fallback without polling. It is never called for the initial `"idle"`,
nor before `createShaderBackground()` returns. Calling `destroy()` from it is
safe.

`hexToRgb("#7dd3fc")` and `hexToRgba("#0f172acc")` turn hex colors into
`vec3` / `vec4` uniform values, and `glslUtils` (from `@frapx/fx-canvas/glsl`)
holds small GLSL snippets such as `glslUtils.coverUv` for cover-fitting an
image texture.

For the full option list, GLSL helpers, color-uniform helpers, and feedback
details, see the [package README](https://github.com/kramhash/frapx/blob/main/packages/fx-canvas/README.md)
and [CHANGELOG](https://github.com/kramhash/frapx/blob/main/packages/fx-canvas/CHANGELOG.md)
on GitHub — or try it live on the [Live Demo](/frapx/live-demo/) page.

## Hot reloading

`setFragment(source)` swaps the shader without recreating the instance, so the
time, uniforms, textures and feedback history carry over. A compile error is
returned (and sent to `onError`) instead of thrown, with the located lines in
`error.lines`, and the previous shader keeps drawing.
[`@frapx/tool-dev`](/frapx/packages/tool-dev/) shows those errors on the page
and has the Vite HMR wiring.

## Timelines

`fx.bindUniforms(source)` drives uniforms from any `{ get(time) }` source,
evaluated with the same time as `u_time` before every draw. `keyframes()` is a
dependency-free one:

```ts
import { keyframes } from "@frapx/fx-canvas";

fx.bindUniforms(keyframes({ camPos: [[0, [0, 1, 6]], [4, [3, 1.5, 2]]] }));
```

## Depends on

`@frapx/fx-canvas` depends on [`@frapx/core`](/frapx/packages/core/), the
internal WebGL lifecycle engine. You never import `@frapx/core` yourself —
it's pulled in automatically.

## Pairs with

- [`@frapx/react-canvas`](/frapx/packages/react-canvas/) if you're in React.
- [`@frapx/glsl-noise`](/frapx/packages/glsl-noise/) / [`@frapx/glsl-flowmap`](/frapx/packages/glsl-flowmap/) for ready-made GLSL snippets inside your `fragment`.
