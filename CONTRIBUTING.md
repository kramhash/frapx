# Contributing to frapx

Thanks for your interest in frapx. Bug reports, questions, examples and pull
requests are all welcome.

**日本語での issue・Discussion も歓迎します。** Write in whichever of English or
Japanese you are comfortable with; replies follow your language where possible.

## Where to start

- **Found a bug?** [Open a bug report](https://github.com/kramhash/frapx/issues/new?template=bug_report.yml).
  A minimal shader or a link to a reproduction helps the most.
- **Have an idea?** [Open a feature request](https://github.com/kramhash/frapx/issues/new?template=feature_request.yml).
  Describe what you are trying to build before the API you have in mind.
- **Made something with frapx?** Share it in
  [Discussions](https://github.com/kramhash/frapx/discussions).
- **Want to write code?** Issues labelled
  [`good first issue`](https://github.com/kramhash/frapx/labels/good%20first%20issue)
  are scoped to be picked up without knowing the whole codebase.

Comment on an issue before you start working on it, so two people do not
work on the same thing.

## Development setup

Requirements: Node.js 22 or later and [pnpm](https://pnpm.io/). The pnpm
version is pinned in `package.json` under `packageManager`; any pnpm 9.7 or
later switches to that version on its own, so an existing install needs no
extra step. Without pnpm, install it with one of the methods on
[pnpm.io/installation](https://pnpm.io/installation).

```sh
pnpm install
pnpm build      # packages export their built dist, so build before anything else
pnpm typecheck
pnpm test       # unit tests (Vitest)
pnpm test:e2e   # browser tests (Playwright); run `pnpm exec playwright install chromium` once
pnpm dev        # the basic example at examples/vite-basic
pnpm dev:docs   # the documentation site
```

## Repository layout

This is a pnpm monorepo. Packages are named by category:

- `packages/fx-*` — effect runtimes (`fx-canvas`, `fx-passes`, `fx-particles`)
- `packages/react-*` — React bindings for an `fx-*` runtime
- `packages/glsl-*` — GLSL snippets to concatenate into your own shader
- `packages/tool-*` — export and development tools
- `packages/core` — the shared WebGL host behind the runtimes (internal)
- `examples/*` — runnable examples, also used as integration checks
- `apps/docs` — the documentation site (Astro + Starlight)

## Guidelines for changes

- **Keep `@frapx/fx-canvas` small.** New capabilities such as larger GLSL
  libraries or presets usually belong in a separate package. If unsure, open
  an issue first.
- **WebGL1 stays the default** for `@frapx/fx-canvas`. WebGL2 features are
  capability-detected and additive. `fx-passes` and `fx-particles` are
  WebGL2-only by design.
- **Importing must stay safe during SSR** — no `window` or `document` access at
  module load.
- **No new production dependencies** without discussing it in an issue first.
  When you add any dependency with an install script, allow (`true`) or deny
  (`false`) it under `allowBuilds` in `pnpm-workspace.yaml`; otherwise
  `pnpm install` fails with `ERR_PNPM_IGNORED_BUILDS`. pnpm also does not
  resolve versions published less than a day ago (`minimumReleaseAge`).
- **Avoid breaking public API.** Exports from each package's `src/index.ts` are
  public; if a change affects them, update the package README and the docs
  page in `apps/docs` too.
- **Add tests** next to the code you change (`packages/*/test`, and
  `packages/*/e2e` for behaviour that needs a real browser).
- **Record user-facing changes** in the package's `CHANGELOG.md` under a
  `## Unreleased` heading (`### Added`, `### Changed`, `### Fixed` or
  `### Documentation`). Releases are cut by the maintainer; see
  [`RELEASING.md`](./RELEASING.md).
- Do not commit `packages/*/dist`; it is generated by `pnpm build`.

## Pull requests

- One topic per pull request. If it resolves an issue, write `Closes #N` in
  the description.
- Make sure `pnpm build`, `pnpm typecheck` and `pnpm test` pass. CI runs them
  together with the E2E tests.
- For visual changes, a screenshot or short clip in the description helps the
  review.
